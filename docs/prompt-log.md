## 5. 개선 2차: 블록 쌓고 올라가기

**프롬프트**

> 회전 cube 제거. 떨어지는 obstacle을 테트리미노 블록으로(높이 1, ProBuilder로 만들고 instantiate).
> 10x10 필드를 정수 칸으로 나누고, 블록이 칸에 딱 맞게 떨어져서 쌓인다.
> 블록을 피하면서 쌓인 블록을 딛고 올라가는 플레이. 높이를 UI로. 조작감 개선.
> 낙하 알고리즘은 불합리하지 않고 자연스럽게. 애매하면 질문.
> (진행 중 추가) 점프로는 한 번에 한 칸씩만. 프로젝트 이름 변경은 맨 마지막에.

**물어본 것과 내 답**

- Game Over 조건 → 떨어지는 중인 블록에 닿으면 (착지한 건 안전)
- 점수 → 지금 서 있는 높이
- 블록 모양 → 테트리미노 7종, 눕혀서
- 조작감 → 점프, 가속/감속, 카메라 따라가기
- 착지 예고 → 그림자 + 빨간 외곽선
- 난이도 → 점점 빨라짐
- 남은 Cube 4개 → 전부 제거, 격자선은 안 그림

**Claude가 한 일**

- ProBuilder 설치, 블록 프리팹 7종 생성
- 스크립트 추가: `FieldGrid`(칸별 높이), `FallingBlock`(대기→낙하→착지), `BlockSpawner`(자리 고르기), `CameraFollow`
- `PlayerController`를 물리 기반으로 다시 짬 (점프, 가감속 등)
- `SphereSpawner` 삭제
- 자세한 건 [개선 2차](update-2-blocks.md)

## 8. 개선 3차: 빈칸 채우기

**프롬프트**

> 블록이 2개 겹쳤다고 가정함. 위에 있는 블록의 한 칸 아래가 비어 있는 칸이라면 아래로 떨어져 채우는 게 좋지 않을까? 어떻게 생각함?

**Claude의 의견**

- 좋은 생각이라고 봄. 지형이 칸마다 높이 하나가 되고, 올라갈 길이 예측하기 쉬워짐
- 걱정: 예고 없이 맞을 수 있음, 테트리미노 모양이 깨짐, 블록을 칸 단위로 다시 짜야 함

**내 답**

> 일단 예고 없이 ㄱㄱ, 불합리함은 테스트해봄. 테트리미노는 예시니까 별 생각 없음, 모래 테트리스도 블록은 깨지잖아. 하면 되잖아.

**Claude가 한 일**

- 착지할 때 밑이 빈 칸이 있으면 블록을 칸 4개(`BlockCell`)로 쪼개고, 빈칸 위의 칸만 떨어뜨림
- 떨어지는 칸도 닿으면 Game Over (`IFallingHazard`로 블록과 같은 규칙)
- 스포너의 "빈 공간" 감점 제거. 자세한 건 [개선 3차](update-3-fill-gaps.md)

## 중간에 막혔던 것

| 상황 | 원인 | 해결 |
|---|---|---|
| TMP 기본 리소스 import 실패 | 클래스가 있는 어셈블리 이름을 잘못 씀 | 어셈블리 검색해서 다시 호출 |
| MCP 코드 실행 컴파일 에러 | `Object`가 `object`랑 헷갈림 | `GameManager.Instance`로 바꿈 |
| Play 중 시간이 거의 안 감 | Unity 창이 비활성이라 프레임이 느림 | 조금 기다렸다가 다시 확인 |
| `Rotator.cs`가 `public`으로 돌아감 | 내가 실수로 변경 사항을 discard함 | 다시 수정. Play 중 스크립트가 바뀌어서 Play도 같이 꺼졌음 |
| MCP로 R키 입력을 넣어도 반응 없음 | Game 뷰에 포커스가 없으면 Input System이 키보드 입력을 버림 | 재시작 함수를 직접 호출해서 로직만 확인. 키는 직접 테스트 |
| `Block.cs`가 컴파일 대상에서 빠짐 | 원인 못 찾음. 다른 파일은 다 들어가는데 이 파일만 빠짐 | 클래스 이름을 `FallingBlock`으로 바꾸니 해결 |
| 시작하자마자 Game Over | 블록이 원점(플레이어 위치)에 한 프레임 생겼다가 옮겨짐 | 처음부터 공중 위치에 `Instantiate` |
| 옆 칸에 떨어진 블록에 스치기만 해도 죽음 | 캡슐 반지름 0.5가 칸을 꽉 채움 | 반지름 0.35로 줄임 |
