# 프롬프트·결과 로그

2026-10-26 / Unity 6.3 (6000.3.26f1), URP

Claude Code에 보낸 주요 요청과, Claude가 한 작업, 제가 확인한 결과를 순서대로 정리했습니다. 인용문은 제가 보낸 프롬프트입니다.

## 1. 공 피하기 게임

> 공 피하기 게임 프로토타입. (과제 사양 표 붙여넣음)
> 플레이어는 WASD 이동. 애매한 부분은 질문하고 확인받을 것.

Claude는 먼저 프로젝트 설정을 확인했습니다. Input System이 New 전용이라 `Keyboard.current`로 키 입력을 받기로 했습니다. 이어서 애매한 부분 4가지를 물어봤고, 저는 이렇게 정했습니다.

- Cube 위치: 에디터에서 한 번만 랜덤 배치
- Game Over 후: Sphere 생성 중지, 떨어진 Sphere는 8초 뒤 삭제
- 플레이어 이동 범위: Ground(10×10) 밖으로 못 나가게
- 시간 표시: `Time: 12.3s`

그다음 스크립트 4개(`Rotator`, `PlayerController`, `SphereSpawner`, `GameManager`)를 작성했습니다. 씬은 MCP로 구성했습니다(Ground, Cube 5개와 머티리얼, Player, 카메라와 조명, UI).

- [x] Sphere가 3초마다 생성되어 중력으로 떨어집니다
- [x] Sphere에 맞으면 Console에 `Game Over`가 한 번 출력됩니다
- [x] Game Over 후 시간이 멈춥니다 (게임 시간 9.1초일 때 생존시간 4.58초 유지)
- [x] Game Over 후 새 Sphere가 생기지 않습니다
- [x] Cube1이 Y축으로 회전하고, Inspector 값은 90입니다
- [x] WASD 이동 (MCP로는 키 입력을 넣을 수 없어 직접 확인)

## 2. GitHub 업로드

> 이 프로젝트 github에 올리게 repo 만들어주셈

공개 범위와 이름을 물어봐서 Public, `MyAvoidSphereGame`으로 정했습니다. Claude가 Unity용 `.gitignore`를 만들고, 첫 커밋 후 repo를 생성해 올렸습니다(파일 170개).

## 3. 문서 작성과 코드 수정

> docs 폴더 만들고 문서 생성. 사람이 쓴 것처럼, 짧고 읽기 쉽게.
> public 썼던데 난 캡슐화 때문에 [SerializeField]를 선호함.

스크립트 4개의 Inspector용 `public` 필드를 `[SerializeField] private`으로 바꿨습니다. 바꾼 뒤에도 Inspector 값(90, 5, 4.5, 3, 머티리얼과 텍스트 참조)이 그대로인 것을 확인했습니다. 이어서 스크린샷을 찍고 문서를 작성했습니다.

## 4. 개선 1차: 재시작

> 추가 도전 A. 1차: game over 후 restart 기능, docs에 문서화, 커밋.
> 2차는 블록 쌓기 프로토타입. 둘을 worktree로 병렬 진행할 수 있는지도 체크.

병렬 진행은 하지 않았습니다. 두 단계가 같은 스크립트와 씬 파일을 고치고, Unity MCP는 에디터 하나에만 연결됩니다. 2차가 1차의 게임 루프 위에서 돌아가기도 해서 순서대로 진행했습니다.

재시작 방식은 R키와 안내 문구로 정했습니다. 자세한 내용은 [개선 1차](update-1-restart.md)에 있습니다.

- [x] Game Over 문구가 뜨고, 재시작하면 상태가 초기화됩니다
- [x] R키로 재시작 (직접 확인)

## 5. 개선 2차: 블록 쌓고 올라가기

> 회전 cube 제거. 떨어지는 obstacle을 테트리미노 블록으로(높이 1, ProBuilder로 만들고 instantiate).
> 10x10 필드를 정수 칸으로 나누고, 블록이 칸에 딱 맞게 떨어져서 쌓인다.
> 블록을 피하면서 쌓인 블록을 딛고 올라가는 플레이. 높이를 UI로. 조작감 개선.
> 낙하 알고리즘은 불합리하지 않고 자연스럽게. 애매하면 질문.
> (진행 중 추가) 점프로는 한 번에 한 칸씩만. 프로젝트 이름 변경은 맨 마지막에.

질문에 대한 제 결정은 이렇습니다.

| 질문 | 결정 |
|---|---|
| Game Over 조건 | 떨어지는 중인 블록에 닿으면. 착지한 블록은 안전 |
| 점수 | 지금 서 있는 높이 |
| 블록 모양 | 테트리미노 7종, 눕혀서 |
| 조작감 | 점프, 가속·감속, 카메라 따라가기 |
| 착지 예고 | 그림자에 빨간 외곽선을 넣어 강조 |
| 난이도 | 점점 빨라지게 |
| 남은 Cube 4개 | 전부 제거, 격자선은 그리지 않음 |

Claude는 ProBuilder를 설치해 블록 프리팹 7종을 만들었습니다. 스크립트도 새로 추가했습니다(`FieldGrid`, `FallingBlock`, `BlockSpawner`, `CameraFollow`). `PlayerController`는 물리 기반으로 다시 짰고, `SphereSpawner`는 지웠습니다. 자세한 내용은 [개선 2차](update-2-blocks.md)에 있습니다.

## 6. 이름 변경

> 이에 따라 프로젝트 이름이랑 관련된 부분도 변경. 대충 적당하게. (맨 마지막 스텝으로)

이름은 `StackClimb`로 정했습니다. GitHub repo 이름을 바꿨고(https://github.com/GaaamJ/StackClimb), Unity Product Name, README, 문서 목록 소개도 바꿨습니다.

이 로그에 나오는 옛 이름(`MyAvoidSphereGame`)은 당시 기록이라 그대로 뒀습니다. 로컬 폴더 이름도 바꾸지 않았습니다. Unity가 열려 있는 상태에서 바꾸면 에디터와 MCP 연결이 끊기기 때문입니다.

## 7. Game Over 연출

> 프로젝트 이름 바꾸고 나면 game over 시 모든 block이 rotator로 rotate하게 해 주셈 재밌잖어

Game Over가 되면 모든 블록에 `Rotator`를 붙여 돌게 했습니다. 자세한 내용은 [개선 2차](update-2-blocks.md)에 있습니다.

## 8. 개선 3차: 빈칸 채우기

> 블록이 2개 겹쳤다고 가정함. 위에 있는 블록의 한 칸 아래가 비어 있는 칸이라면 아래로 떨어져 채우는 게 좋지 않을까? 어떻게 생각함?

Claude는 좋은 방향이라고 봤습니다. 다만 예고 없이 맞을 수 있다는 점, 테트리미노 모양이 깨진다는 점, 블록을 칸 단위로 다시 짜야 한다는 점을 걱정했습니다. 제 답은 이랬습니다.

> 일단 예고 없이 ㄱㄱ, 불합리함은 테스트해봄. 테트리미노는 예시니까 별 생각 없음, 모래 테트리스도 블록은 깨지잖아. 하면 되잖아.

착지할 때 밑이 빈 칸이 있으면 블록을 칸 4개(`BlockCell`)로 쪼개고, 빈칸 위의 칸만 떨어뜨리게 했습니다. 떨어지는 칸에 닿아도 Game Over입니다. 자세한 내용은 [개선 3차](update-3-fill-gaps.md)에 있습니다.

## 9. 개선 4차: 웨이브

> 시간이 지나며 한 번에 많은 블록이 약간의 랜덤한 간격을 두고 떨어지도록. 아무것도 없을 때도 일정 개수 이상으로 시작. 1개는 너무 적어서 쉬움. 애매한 점 있으면 질문.

웨이브 크기와 간격, 노리는 블록 수를 질문받았습니다. 수치는 추천값으로 먼저 넣고, 직접 플레이하면서 조정하기로 했습니다.

> 적정값은 일단 네가 추천해주는 걸로 가 보고 내가 해 보면서 수정해 봄

씬에 저장돼 있던 옛 값도 새 값으로 맞췄습니다. Inspector 값이 코드 기본값보다 우선하기 때문입니다. 자세한 내용은 [개선 4차](update-4-waves.md)에 있습니다.

## 중간에 막혔던 것

| 상황 | 원인 | 해결 |
|---|---|---|
| TMP 기본 리소스 import 실패 | 클래스가 있는 어셈블리 이름을 잘못 지정 | 어셈블리를 검색해서 다시 호출 |
| MCP 코드 실행 중 컴파일 에러 | `Object`가 `object`와 모호함 | `GameManager.Instance`로 변경 |
| Play 중 시간이 거의 안 감 | Unity 창이 비활성이라 프레임이 느림 | 테스트 중에만 `runInBackground` 켜기 |
| `Rotator.cs`가 `public`으로 돌아감 | 제가 실수로 변경 사항을 discard함 | 다시 수정. Play 중 스크립트가 바뀌어 Play도 같이 꺼짐 |
| MCP로 R키를 넣어도 반응 없음 | Game 뷰에 포커스가 없으면 Input System이 키 입력을 버림 | 재시작 함수를 직접 호출해 로직만 확인하고, 키는 직접 테스트 |
| `Block.cs`가 컴파일 대상에서 빠짐 | 원인 불명. 이 파일만 빠짐 | 클래스 이름을 `FallingBlock`으로 바꾸니 해결 |
| 시작하자마자 Game Over | 블록이 원점(플레이어 위치)에 한 프레임 생겼다가 옮겨짐 | 처음부터 공중 위치에 생성 |
| 옆 칸 블록에 스치기만 해도 Game Over | 캡슐 반지름 0.5가 칸을 꽉 채움 | 반지름을 0.35로 줄임 |
