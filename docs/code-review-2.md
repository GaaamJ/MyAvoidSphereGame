# 코드 리뷰 2: 5차까지의 전체 스크립트

개선 5차까지 끝난 시점에서 `Assets/Scripts`의 스크립트 전체를 간단히 다시 봤습니다. 기능은 테스트로 확인된 상태라, 여기서는 당장 깨지는 버그보다 나중에 문제가 될 수 있는 부분을 위주로 적었습니다.

## 구조

| 스크립트 | 역할 |
|---|---|
| `GameManager` | 생존시간과 높이 표시, Game Over, R키 재시작 |
| `PlayerController` | 이동, 점프, 착지 판정, 피격 판정, 찌그러짐 연출 |
| `FieldGrid` | 칸마다 쌓인 높이 기록, 칸과 월드 좌표 변환 |
| `BlockSpawner` | 웨이브 생성, 떨어질 자리 고르기 |
| `FallingBlock` | 블록 대기, 낙하, 착지, 착지 예고, 칸 쪼개기 |
| `BlockCell` | 쪼개진 한 칸의 낙하 |
| `LandingEffects` | 착지 먼지, 카메라 흔들림 호출 |
| `CameraFollow` | 높이 따라가기, 흔들림 |
| `IFallingHazard` | "떨어지는 중이면 위험" 규칙 |
| `Rotator` | 회전 (Game Over 연출에 재사용) |

## 잘 된 점

- 역할이 스크립트별로 잘 나뉘어 있습니다. 특히 칸 높이 계산은 `FieldGrid`에만 있어서, 3차에서 빈칸 채우기를 넣을 때도 고칠 곳이 적었습니다.
- 위험 판정을 `IFallingHazard` 하나로 묶어서, 블록과 쪼개진 칸을 플레이어가 같은 방식으로 처리합니다.
- Inspector 값은 모두 `[SerializeField] private`이고, 다른 스크립트가 읽어야 하는 값만 읽기 전용 프로퍼티로 열려 있습니다.
- 수치마다 Tooltip이 있어서, 직접 조정할 때 의미를 바로 알 수 있습니다.

## 개선할 점

| 중요도 | 위치 | 내용 | 제안 |
|---|---|---|---|
| 중 | `FallingBlock.Init`, `BlockSpawner.Spawn` | 블록 위치는 `Field`의 위치를 더해서 계산하는데, 낙하 시작·착지 높이(`startY`, `landY`)는 더하지 않습니다. 지금은 `Field`가 y=0이라 문제없지만, 필드를 위아래로 옮기면 블록이 엉뚱한 높이에서 멈춥니다. | 높이 계산도 `FieldGrid`가 맡도록 `LevelToWorldY` 같은 함수를 하나 두기 |
| 중 | `BlockSpawner.Spawn` | 플레이어가 서 있는 층을 `player.position.y - 1f`로 구합니다. 캡슐 높이(2)를 숫자로 박아 둔 것이라, 캐릭터 크기를 바꾸면 도망갈 칸 판정이 틀어집니다. | `PlayerController`가 현재 층을 프로퍼티로 알려 주고, 스포너는 그 값을 쓰기 |
| 하 | `FallingBlock.BuildMarkerMesh` | 착지 예고를 매 프레임 다시 만들면서 리스트와 HashSet을 새로 할당합니다. 블록이 많아지면 GC가 조금씩 쌓입니다. | 리스트를 필드로 두고 재사용하거나, 그림자만 따로 스케일 조절 |
| 하 | `FallingBlock.SplitIntoCells` | 블록이 쪼개지면 원래 블록은 렌더러와 콜라이더만 끄고 남겨 둡니다. 판에 보이지 않는 오브젝트가 계속 늘고, Game Over 때는 이것들에도 `Rotator`가 붙습니다. | 쪼개진 칸이 다 떨어지고 `Landed`를 보낸 뒤 원래 블록은 `Destroy` |
| 하 | `BlockSpawner.Spawn` | 후보 12개 중 조건을 만족하는 자리가 없으면 그 블록은 그냥 건너뜁니다. 필드가 많이 차면 웨이브 블록 수가 말없이 줄 수 있습니다. | 노리는 블록이 실패하면 안 노리는 블록으로 한 번 더 시도 |
| 하 | `GameManager`, `LandingEffects` | `Instance`를 `Awake`에서 넣기만 하고 비우지 않습니다. 지금은 씬을 통째로 다시 불러와서 괜찮지만, 씬이 여러 개가 되면 사라진 오브젝트를 가리킬 수 있습니다. | `OnDestroy`에서 자기 자신이면 `Instance = null` |

## 정리

규모에 비해 구조는 깔끔한 편입니다. 다만 "필드는 y=0", "캐릭터 키는 2" 같은 가정이 코드 곳곳에 숫자로 들어가 있습니다. 다음에 맵이나 캐릭터를 바꾼다면 위 표의 "중"부터 고치는 것이 좋겠습니다. 이번 리뷰에서는 코드를 수정하지 않았습니다.
